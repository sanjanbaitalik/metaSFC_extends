# Prompt 102A — Correct and Harden Audit 101 Before Any NCR or Prior Redesign

## Objective

Correct the implementation of the existing Conditional / Residual Prior-Signal Audit (Audit 101) before making any methodological decision.

Do **not** change NCR.
Do **not** rebuild the prior.
Do **not** change targets, subjects, outer CV splits, or existing benchmark definitions.

The goal of this patch is to make Audit 101 fully leakage-safe, make control comparisons fair, fix the current weighted-Ridge implementation, and regenerate the decision from corrected seed-level results.

---

# Why this patch is necessary

The current Audit 101 implementation contains several problems:

1. **Variant selection uses outer-test performance.**
   The current script evaluates multiple residual variants on the outer-test fold and then chooses the best variant using outer-test `delta_pearson`.

2. **Eta selection is not fully cross-fitted.**
   The residual model can use in-sample predictions on the train/validation set to choose additive weight `eta`.

3. **Matched and control priors are not evaluated symmetrically.**
   The matched prior is evaluated across multiple residual variants, while control priors may be evaluated only with a fixed `topk_0.10` configuration.

4. **Decision labels are inconsistent.**
   The control statistics are stored using labels such as:
   ```text
   shuffled
   random
   unrelated
   ```
   while the decision logic searches for:
   ```text
   matched_vs_shuffled
   matched_vs_random
   matched_vs_unrelated
   ```
   causing `matched_beats_*` fields to remain false regardless of the actual statistics.

5. **Weighted residual Ridge is effectively neutralized by StandardScaler.**
   Multiplying each feature by a positive prior weight and then independently standardizing every feature cancels most/all of the intended prior weighting.

6. **Decision logic pools tasks too aggressively.**
   Fluid and working-memory outcomes should be reported and decided separately before creating any combined summary.

7. **Some decision fields are hard-coded or not derived robustly from outputs.**

The corrected audit must resolve all of these issues.

# Part 2 — Cross-fitted baseline residuals

For each outer-training set:

1. generate out-of-fold predictions from the no-prior FC+SC Ridge baseline;
2. ensure every outer-training subject's baseline prediction comes from a model that did not train on that subject;
3. define:

\[
r_i = y_i - \hat y^{OOF}_{Ridge,i}.
\]

These residuals become the target for residual-branch model selection.

No in-sample baseline residuals are allowed.

---

# Part 3 — Cross-fitted residual-branch predictions

For every candidate residual model, generate **out-of-fold residual predictions** inside the outer-training set.

For candidate configuration \(c\):

\[
\hat r_i^{OOF,c}
\]

must be generated by a residual model that did not train on subject \(i\).

Then form:

\[
\hat y_i^{OOF,c,\eta}
=
\hat y_{Ridge,i}^{OOF}
+
\eta \hat r_i^{OOF,c}.
\]

Select the residual configuration and `eta` using these cross-fitted combined predictions only.

# Part 6 — Fix prior-weighted Ridge correctly

Do not implement prior weighting as:

```python
X_weighted = X * weights
X_weighted = StandardScaler().fit_transform(X_weighted)
```

because independent standardization cancels fixed feature scaling.

Instead implement a true **generalized Ridge penalty**.

For coefficient vector \(\beta\):

\[
\min_\beta
\|y-X\beta\|_2^2
+
\lambda \sum_e d_e \beta_e^2
\]

where:

\[
d_e = (\epsilon + q_e)^{-\gamma}.
\]

Use:

```text
epsilon = 1e-3
gamma ∈ {0.5, 1.0, 2.0}
```

High-prior features receive lower shrinkage.

The feature matrix may still be standardized using training statistics, but the prior must enter through the **penalty matrix**, not through feature scaling that is later normalized away.

Implementation options:

### Option A — transformed ordinary Ridge

Let:

\[
D = diag(d_e)
\]

and reparameterize:

\[
\theta = D^{1/2}\beta.
\]

Then solve Ridge on:

\[
X D^{-1/2}.
\]

Recover:

\[
\beta = D^{-1/2}\theta.
\]

### Option B — direct closed-form generalized Ridge

\[
\hat\beta =
(X^T X + \lambda D)^{-1}X^T y.
\]

Use a numerically stable solver and the repository's existing Woodbury/dual strategy if needed for high-dimensional \(p \gg n\).

Add tests confirming that different `gamma` values produce different penalties/results on synthetic data.

# Part 11 — Decision rules

For each task:

## Strong residual-prediction evidence

If:

```text
matched beats shuffled
matched beats random
median ΔPearson >= +0.010
positive seeds >= 8/10
no material RMSE degradation
```

then:

```text
recommended_next_step = adaptive_residual_ncr
```

## Moderate evidence

If:

```text
matched beats shuffled/random
median ΔPearson >= +0.005
positive seeds >= 7/10
```

then:

```text
recommended_next_step = anisotropic_or_residual_ncr
```

## Residual specificity but tiny prediction gain

If:

```text
matched beats shuffled/random in residual enrichment
but median ΔPearson < +0.005
```

then:

```text
recommended_next_step = anisotropic_ncr
```

## Generic prior

If:

```text
matched does not beat unrelated
and unrelated gives equal/higher incremental prediction
```

then:

```text
recommended_next_step = improve_task_prior_matching
```

## No meaningful matched-prior conditional signal

If:

```text
matched does not beat shuffled/random
and incremental gain is negligible
```

then:

```text
recommended_next_step = rebuild_prior
```

The overall decision should preserve task asymmetry.

For example:

```text
Fluid -> rebuild_prior
WM -> anisotropic_ncr
```

must be allowed.

Do not collapse this to one global recommendation prematurely.
